# Council 4.1 Execution Control Plane Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every managed browser action observable, permissioned, auditable, and mechanically safe around the external ChatGPT submission boundary.

**Architecture:** Add a dedicated in-process `CouncilExecutionControlPlane` between browser transport and external control surfaces. Browser/Playwright emits typed observations; the control plane owns public run state, bounded events, retry safety, cancellation handles, and command receipts; MCP/Electron/Mission Control consume only the public model.

**Tech Stack:** Bun 1.3.14, TypeScript 5.9, Playwright Core 1.62, MCP SDK 1.30, Electron launcher, React.

**Spec:** `docs/superpowers/specs/2026-08-31-council-4.1-execution-control-plane-design.md`

## Global Constraints

- Preserve Council 4.0's fail-closed external submission invariant.
- Never expose conversation URLs, checkpoints, prompts, cookies, tokens, attachment bytes, raw DOM selectors, arbitrary JavaScript, or hidden chain-of-thought through execution APIs.
- Keep event history bounded at 128 events per run and retained runs bounded at 256 by default; active runs are never evicted.
- Reuse existing ACL vocabulary only. `review` authorizes focus/capture; `wake` authorizes cancel/retry. Read access requires an authenticated active Council participant.
- `retry` is rejected at or after `submit-started` and for uncertain, completed, waiting-user, policy, limit, and conversation-unavailable states.
- Existing Council 4.0 MCP tools remain additive-compatible.
- Full `bun run verify`, Electron package, packaged smoke, and Windows/macOS/Ubuntu CI must pass before merge.
