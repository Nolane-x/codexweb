# CodexWeb Council 3.3 Reliability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove split wake semantics, make persistent ChatGPT surfaces recoverable instead of blank/ambiguous, strengthen resurrection continuity, and align product/version documentation with the shipped runtime.

**Architecture:** Keep `CouncilStore` as the single durable Council domain store. Introduce one canonical wake-status normalization boundary used by all delivery paths, enrich browser transport with controller-owned surface lifecycle evidence and recoverable surface reset, and make persistent managed-agent state the source of truth for conversation continuity while runtime surface leases remain ephemeral. Preserve the existing ChatGPT-Web adapter and Council action protocol.

**Tech Stack:** Bun 1.3.14, TypeScript 5.9, Electron 41, Playwright 1.62, React 19, GitHub Actions.

## Global Constraints

- No production behavior change before a failing regression test is committed and observed RED in GitHub Actions.
- `CouncilStore` remains the only durable shared Council store.
- Legacy persisted wake states remain readable, but all newly observable wake states use `queued`, `dispatched`, `target-running`, `replied`, `failed`, or `expired`.
- Arbitrary browser/send failures must never create a second ChatGPT conversation or duplicate a submitted turn.
- Conversation URLs remain private controller state and never enter the public Council projection.
- Managed-agent persisted conversation binding is authoritative across restarts; browser surface ownership is ephemeral.
- Renderer/shared diagnostics expose structured safe states and sanitized errors only.
- README/release/version copy must agree with the package version actually shipped.
