# Council 4.1 Execution Control Plane Design

## Purpose

Council 4.1 turns browser execution from an opaque side effect into a typed, observable, permissioned runtime surface. It must expose enough live execution truth for Mission Control and MCP clients to understand what an agent is doing without allowing the UI or MCP layer to manipulate raw browser internals directly.

The design preserves Council 4.0's strongest safety invariant: once an external ChatGPT submission may have occurred, the runtime must not automatically retry unless non-delivery is proven.

## Goals

1. Represent each managed browser operation as a durable-in-process execution run with a stable run ID and bounded event history.
2. Stream Deep State transitions and transport phases into that run without leaking hidden model reasoning.
3. Expose typed operator commands through one authorization boundary.
4. Make retry eligibility explicit and mechanically derived from the submission boundary.
5. Record immutable audit receipts for every accepted or rejected operator command.
6. Surface runs, events, state, safety status, and repair actions in Mission Control.
7. Expose a focused MCP execution facade rather than direct Playwright primitives.

## Non-goals

- No raw CDP session or arbitrary Playwright script execution through MCP.
- No arbitrary DOM selector tool.
- No automatic retry after an uncertain or observed submission.
- No exposure of private ChatGPT conversation URLs, checkpoints, credentials, cookies, or browser storage.
- No hidden chain-of-thought capture or display.
- No replacement of the existing autonomy work store in this wave.
- No full event-sourced rewrite of Council persistence.

## Architecture

Council 4.1 adds a dedicated Execution Control Plane between managed runtime/browser transport and external control surfaces.

```text
Mission Control          MCP Execution Facade
      │                         │
      └────────────┬────────────┘
                   ▼
        Execution Control Plane
        ├─ Run Registry
        ├─ Event Timeline
        ├─ Command Authorizer
        ├─ Retry Safety Classifier
        └─ Audit Receipt Store
                   │
                   ▼
          Council Browser Transport
                   │
                   ▼
        Playwright Council Driver
                   │
                   ▼
          ChatGPT Deep State Engine
```

The Playwright driver emits observations. It does not know about MCP or Mission Control. The control plane owns run identity, public state, commands, and audit. MCP and renderer consume only the public control-plane model.

## Execution Run Model

Create `src/council/execution-control-plane.ts` as the authority for public execution state.

```ts
export type CouncilExecutionRunKind = "turn" | "focus" | "capture";

export type CouncilExecutionRunStatus =
  | "queued"
  | "active"
  | "waiting-user"
  | "completed"
  | "failed"
  | "aborted"
  | "uncertain";

export interface CouncilExecutionRun {
  runId: string;
  traceId: string;
  agentId: string;
  kind: CouncilExecutionRunKind;
  status: CouncilExecutionRunStatus;
  phase?: CouncilExecutionPhase;
  deepState?: CouncilChatGptState;
  startedAt: string;
  updatedAt: string;
  completedAt?: string;
  retrySafety: "safe-before-submit" | "forbidden-after-submit" | "operator-resolution-required";
  failureCode?: CouncilFailureCode;
  failureMessage?: string;
  surfaceBound: boolean;
  conversationBound: boolean;
  eventCount: number;
}
```

No private URL, prompt body, checkpoint, token, cookie, attachment bytes, or raw page text may appear in the public run model.

## Execution Events

Runs retain a bounded event timeline.

```ts
export type CouncilExecutionEventKind =
  | "run-created"
  | "phase"
  | "deep-state"
  | "health"
  | "command-requested"
  | "command-accepted"
  | "command-rejected"
  | "failure"
  | "completed";

export interface CouncilExecutionEvent {
  eventId: string;
  runId: string;
  kind: CouncilExecutionEventKind;
  at: string;
  phase?: CouncilExecutionPhase;
  deepState?: CouncilChatGptState;
  failureCode?: CouncilFailureCode;
  message?: string;
}
```

Event history is capped at 128 events per run and 256 retained runs by default. Eviction prefers terminal runs oldest-first and must never remove an active run.

Events describe observable runtime behavior only. They must not contain model chain-of-thought.

## Telemetry Integration

Extend the browser transport observer from phase-only callbacks into a typed observation channel while preserving backward compatibility.

```ts
export type CouncilExecutionObservation =
  | { type: "phase"; phase: CouncilExecutionPhase }
  | { type: "deep-state"; state: CouncilChatGptState; confidence: number; reason: string }
  | { type: "health"; health: CouncilObservationHealth; note?: string };

export type CouncilExecutionObserver = (observation: CouncilExecutionObservation) => void;
```

The transport adapter may provide compatibility helpers for current phase emitters. The Playwright driver emits a Deep State observation only when the classified state meaningfully changes, not on every polling iteration.

The public reason string must be bounded and diagnostic, not hidden reasoning.

## Command Model

Supported commands in 4.1:

```ts
export type CouncilExecutionCommand =
  | { type: "cancel"; runId: string }
  | { type: "focus"; agentId: string }
  | { type: "capture"; agentId: string }
  | { type: "retry"; runId: string };
```

### Cancel

`cancel` is valid only for an active run. It aborts the local operation. If the run has reached `submit-started`, cancellation does not imply that the external submission was cancelled. The resulting run must become `uncertain` when delivery cannot be disproven.

### Focus

`focus` reacquires the persistent managed conversation using trusted controller-held identity. It never accepts a conversation URL from renderer or MCP.

### Capture

`capture` performs an observation capture through the existing trusted capture path. It never accepts arbitrary URLs or selectors.

### Retry

`retry` is allowed only when the source run is mechanically classified `safe-before-submit`. A run that reached `submit-started`, `submit-observed`, `response-streaming`, or any later phase is never auto-retryable. An uncertain run requires explicit operator resolution through existing uncertainty handling; `retry` must reject it.

## Authorization

Execution commands use a single authorizer. The caller must be an authenticated Council participant and must possess the appropriate managed permission.

Proposed mapping:

- read runs/events: any authenticated participant in the active managed project
- focus/capture: `inspect`
- cancel: `manage`
- retry: `manage`

The exact permission string names must reuse existing `COUNCIL_PERMISSIONS`; Council 4.1 must not invent a parallel ACL vocabulary. If the existing permission set lacks a clean mapping, the implementation must choose the least-powerful existing permission and document it in tests.

The Electron owner path may issue commands as operator authority, but renderer IPC remains typed and must not accept URLs, raw selectors, tokens, or arbitrary JavaScript.

## Audit Receipts

Every command attempt produces an immutable receipt.

```ts
export interface CouncilExecutionCommandReceipt {
  receiptId: string;
  commandType: CouncilExecutionCommand["type"];
  actorId: string;
  targetRunId?: string;
  targetAgentId?: string;
  requestedAt: string;
  outcome: "accepted" | "rejected";
  reason: string;
  resultingRunId?: string;
}
```

Receipts are bounded, append-only within the control plane, and exposed read-only. Rejected commands are auditable too.

## MCP Execution Facade

Add a focused module `src/council/mcp-tools-execution.ts`.

Initial tools:

- `council_execution_list`
- `council_execution_read`
- `council_execution_events`
- `council_execution_receipts`
- `council_execution_cancel`
- `council_execution_focus`
- `council_execution_capture`
- `council_execution_retry`

All tools require `agent_id` and `agent_token`. Read tools are `readOnlyHint: true`. Command tools are not destructive in the storage sense, but cancel/retry must not claim idempotence unless the implementation proves it.

MCP results expose public run/event/receipt shapes only.

## Mission Control

Add an Execution Inspector to the existing Mission Control rather than creating another overlay.

### Overview

Show active execution count and attention count.

### Agents

An agent row shows current execution state when present:

- Thinking
- Deep thinking
- Streaming
- Tool running
- Waiting for user
- Completing
- Failed
- Uncertain

### Diagnostics / Execution Inspector

Selecting a run shows:

- agent
- run kind
- elapsed time
- current phase
- Deep State
- retry safety
- failure family
- bounded observable timeline
- available operator actions

Abnormal states outrank healthy states visually. `uncertain`, `waiting-user`, `DOM_DRIFT`, rate-limit, connection-loss, and failure states must be visible without opening raw logs.

The UI must never imply that `cancel` cancelled an already-submitted ChatGPT request unless the runtime has evidence of non-delivery.

## Failure Semantics

Extend failure classification where needed so Deep State families retain their identity through the control plane. At minimum Council 4.1 must distinguish:

- capacity busy
- surface unavailable
- conversation unavailable
- ChatGPT limited
- ChatGPT signed out
- connection failed
- response stalled
- DOM drift
- waiting for user
- submission uncertain
- unknown

Failure messages are bounded and sanitized.

## Retry Safety Invariant

The retry classifier is pure and independently tested.

```ts
retrySafety(phase, status, failureCode)
```

Rules:

1. Before `submit-started`, retry may be safe only for explicitly retryable transport failures.
2. At or after `submit-started`, automatic retry is forbidden.
3. If submission delivery cannot be established, state is `operator-resolution-required`.
4. `completed`, `waiting-user`, policy/budget failures, conversation-unavailable, and user-visible limits are never auto-retried.
5. No caller may override the classifier with a boolean flag.

## Lifecycle

Typical successful turn:

```text
run-created
→ lease-acquired
→ conversation-ready
→ connector-selected? (optional)
→ prompt-attached
→ files-attached
→ submit-started
→ submit-observed
→ deep-state: THINKING
→ deep-state: DEEP_THINKING
→ deep-state: STREAMING
→ response-streaming
→ deep-state: COMPLETING
→ deep-state: COMPLETED
→ response-complete
→ completed
```

Connector absence is not a failure event when browser-only Council remains usable.

## Testing Strategy

### Pure unit tests

- run creation and bounded retention
- state transition/event deduplication
- retry-safety classifier
- audit receipt creation
- command authorization
- redaction/no-private-fields contract

### Browser transport tests

- phase observations feed the run registry
- Deep State changes feed events only on meaningful transitions
- cancel before submit ends as aborted and may permit safe retry only for an eligible failure
- cancel after submit never claims delivery cancellation
- uncertain submission cannot be retried

### MCP contract tests

- eight execution tools register only when the control plane exists
- every tool requires authenticated actor credentials
- public responses contain no conversation URL/checkpoint/token
- retry/cancel permissions are enforced

### Mission Control tests

- execution workspace/inspector is part of the single Mission Control shell
- current execution status appears on agent rows
- abnormal states are surfaced before healthy details
- action availability follows public retry/permission state

2. launcher typecheck/tests
3. Electron package
4. packaged smoke
5. GitHub Actions Windows/macOS/Ubuntu all green

## Migration and Compatibility

- Existing Council 4.0 MCP tools remain available.
- Existing phase-based callers continue working through a compatibility adapter while internal code migrates to typed observations.
- No persisted Council state schema is migrated in 4.1; the execution registry is intentionally runtime-scoped and bounded.
- MCP server version increments additively.
- Mission Control changes are additive within the current shell; no legacy overlay is reintroduced.

## Acceptance Criteria

Council 4.1 is complete when:

1. Every managed browser action visible to operators has a run ID and bounded timeline.
2. Deep State transitions are observable outside the Playwright driver without exposing hidden reasoning.
3. MCP clients can inspect execution state and invoke only typed, authorized commands.
4. Retry cannot cross the submission boundary.
5. Every command attempt produces an audit receipt.
6. Mission Control presents execution state and repair/action affordances without another overlay.
7. No private conversation URL, checkpoint, token, cookie, selector, or arbitrary script crosses into renderer/MCP results.
8. Full CI verify/package/smoke passes on Windows, macOS, and Ubuntu.
