# CodexWeb Council 3.6.0

Council 3.6 extends the durable autonomy kernel with bounded project memory, deduplicated visual evidence, stale-work recovery, deterministic team-policy hints, and explicit human recovery for ambiguous post-submit work.

## Durable project memory

- Adds a private, versioned memory index for high-value Council facts with bounded retention and provenance.
- Memory entries preserve source type/source id, project room, author/agent attribution where available, timestamps, and bounded text instead of replaying unbounded transcripts.
- Read surfaces expose safe project knowledge without leaking conversation URLs, credentials, local paths, private checkpoints, screenshot bytes, or raw browser state.
- Supervisor observation history can contribute a bounded memory digest so a resurrected manager can understand recent team health without replaying every observation.

## Deduplicated evidence

- Adds a content-addressed evidence store for retained screenshot evidence.
- Identical image payloads are stored once and referenced by digest, reducing repeated long-running observation storage.
- Evidence metadata is bounded and separate from public Council state; screenshot bytes remain private to the local managed runtime.

## Stale-work recovery

- Adds a stale-task monitor for `claimed`, `in_progress`, `review`, and `blocked` work owned by managed agents.
- Staleness is measured from the task revision timestamp, not from a polling counter.
- One unchanged stale task revision produces at most one escalation; a genuine task revision can later produce a new escalation if it becomes stale again.
- Active agents are not escalated merely because a task is old, and Council never invents a manager when none is selected.

## Team-policy hints

- Adds deterministic candidate hints for manager decisions using task/role/health evidence.
- Hints are advisory and reproducible; they do not silently reassign work or bypass the existing Council permission model.
- Limited, signed-out, missing-surface, disconnected, stalled, and quarantined candidates can be filtered or penalized so the manager is not encouraged to hammer unhealthy agents.

## Health anti-flapping

- Managed-agent health transitions now retain conservative failure evidence and avoid declaring recovery from weak or contradictory signals.
- Sleeping remains a healthy idle lifecycle state rather than a failure.
- Strong healthy evidence is required to clear persistent sign-out/quarantine-style conditions where automatic recovery would be unsafe.

## Operator recovery for uncertain submissions

- Work whose ChatGPT submission crossed the persisted submit boundary but lacks a provable result remains `uncertain`.
- Council never automatically retries such a turn.
- Recovery is human/operator mediated: the operator can resolve the ambiguous item only after checking the target conversation/evidence and deciding whether the original turn actually ran.
- Wake receipt reconciliation continues to favor proof over duplicate delivery.

## Safety and compatibility

- Council 3.5 rooms, agents, tasks, decisions, wake records, durable autonomy work, health, audit data, managed conversation bindings, checkpoints, and supervisor history remain compatible.
- New memory/evidence stores are additive, versioned, private, and bounded.
- Browser-affecting managed work remains globally serialized and subject to Council 3.5 budgets/circuit breakers.
- `bun run verify`, Electron packaging, and packaged smoke remain required across macOS, Windows, and Ubuntu before release integration.
