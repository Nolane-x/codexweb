# CodexWeb Council 3.4.0

Council 3.4 closes the managed-agent supervision loop around persistent ChatGPT Web conversations.

## Project Manager supervisor

- Pick exactly one managed ChatGPT agent as Project Manager from Electron.
- Selection starts an initial supervisor pass after a short startup delay and then repeats every 20 minutes until the manager selection is cleared.
- Supervisor passes never overlap.
- Every managed agent is inspected sequentially: Council resumes the saved conversation, scrolls the conversation surface to the bottom, captures the visible bottom viewport, records safe health evidence, releases the browser lease, and only then moves to the next agent.
- The selected manager receives the captured screenshots, current Council tasks/wakes/messages, agent health manifest, and bounded retained observation memory in one managed turn.
- Manager wake/spawn/review actions flow through the same sequential browser-work scheduler, preventing automation fan-out storms.

## Failure awareness and recovery

Observation health distinguishes healthy, sleeping, busy, usage-limited/rate-limited, signed-out/session failures, missing conversations, missing browser surfaces, connection failures, stalled responses, and unknown failures.

Spawn and wake no longer strand a managed agent merely because browser capacity is temporarily unavailable. Managed browser work is queued and uses bounded retry only for failures known to occur before message submission, avoiding duplicate ChatGPT turns after uncertain send failures.

## Real Council connector on managed turns

Managed ChatGPT turns now select the exact `CodexWeb Council` connector in the composer and require ChatGPT's selected-connector marker before prompt submission. Tool approval is handled on the owned browser surface while Electron keeps managed identity/control state private.

## Retained observation memory

Council stores supervisor history in its private local data directory:

- versioned run metadata;
- per-agent health records;
- bottom-of-chat PNG captures;
- manager analysis;
- bounded memory digest for future manager continuity.

The default retention budget is 72 runs / 512 MiB with oldest-first pruning. Electron can list/read/delete individual observations or clear the archive. Authenticated Council agents can read safe retained observation metadata/analysis through `council_observation_list` and `council_observation_read`; local filesystem paths, conversation URLs, owner credentials, and screenshot bytes are not exposed through those MCP tools.

## Electron project workspace

The ChatGPT workspace now includes Chrome-like project tabs for managed agents, including parked/sleeping agents whose conversation is persisted but whose browser surface is not currently leased. A Manager panel exposes selection, cadence, queue state, manual scan, retained observation history, screenshot inspection, deletion, and manager analysis.

## Safety boundaries

- Browser-affecting managed work is globally serialized.
- Observation capture is read-only and never submits a prompt.
- User clearing the manager disables future automatic scans.
- Active observation history cannot be deleted from the normal UI while a scan is running.
- Owner-only history/supervisor operations stay behind loopback bearer authentication and Electron main-process IPC.
- Screenshot archives use private filesystem permissions where supported and are surfaced to the renderer only as explicit image data, not local paths.
