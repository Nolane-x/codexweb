# CodexWeb Council 3.3.0

Council 3.3.0 is a reliability release for wake routing, persistent ChatGPT browser surfaces, resurrection continuity, and operator observability.

## Reliability

- Unified new wake delivery around the canonical lifecycle `queued → dispatched → target-running → replied`, with `failed` and `expired` terminal states.
- Preserved compatibility with persisted legacy `pending`, `delivering`, and `acknowledged` wakes while normalizing those states at the public Council projection boundary.
- Fixed the fallback wake engine ignoring newly created canonical `queued` wakes.
- Added explicit pre-submit browser-surface failure handling for closed or `about:blank` surfaces.
- A recoverable pre-submit surface failure releases the agent binding and reacquires one surface exactly once.
- Arbitrary send/network/response failures are never retried, preventing duplicate ChatGPT turns.

## Continuity

- Persistent managed-agent conversation URLs remain the controller-owned source of truth across process restarts.
- Resurrection data now highlights unfinished commitments assigned to the resumed agent, alongside checkpoint, recent messages, decisions, tasks, and wake reason.
- Completed work is excluded from the unfinished-commitments capsule.

## Observability

- Public Council snapshots expose canonical wake lifecycle semantics even when reading legacy persisted records.
- The Council dock now renders a compact wake transition timeline with timestamps.
- Private conversation URLs, credentials, tokens, and transport internals remain outside the shared renderer projection.

## Safety and compatibility

- `CouncilStore` remains the single durable shared Council store.
- Shared Council visibility remains independent from local execution capability health.
- Existing Council 3.2 persisted state remains readable.
- Existing ChatGPT conversations are reused unless the conversation itself is explicitly unavailable; browser-surface recovery is not treated as conversation loss.

## Verification gate

The release SHA must pass `bun run verify`, native Electron package, and packaged-app smoke on Linux, macOS, and Windows before merge/tag. Stable release publication additionally requires the repository release workflow matrix and checksummed assets.
