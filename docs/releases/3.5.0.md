# CodexWeb Council 3.5.0

Council 3.5 replaces fragile in-memory autonomous intent with a durable, restart-safe autonomy kernel while preserving Council's conservative no-duplicate-turn boundary.

## Durable autonomy kernel

- Wake, spawn, task routing, review routing, manager observations, captures, and escalations are represented as durable work intents before browser work begins.
- Active intents use stable dedupe keys, priority/FIFO leasing, bounded retries, lease heartbeats, and atomic private persistence.
- Queued work survives Core/Electron restarts.
- Expired work known to be pre-submit is safely recovered; work that crossed `submit-started` without a proven completion becomes `uncertain` and is never retried automatically.
- `CouncilWorkScheduler` remains the final in-process serialization guard, so only one browser-affecting managed operation executes at a time.

## Event-driven team routing

- A non-complete task assigned to a sleeping/parked managed agent can create one coalesced durable wake immediately instead of waiting for the next 20-minute screenshot scan.
- Review assignments create review-routing wake intent.
- Explicit Council mentions can wake the named managed participant, while the resurrection prompt tells the agent to act only when the current project state actually requires it.
- Existing Council 3.4 active wake records are imported into the durable queue idempotently on startup.
- Wake/spawn effects produced by managed ChatGPT agents re-enter the same durable queue rather than recursively starting parallel browser automation.

## Submission-boundary safety

Managed ChatGPT execution now records monotonic phases:

`lease-acquired → conversation-ready → connector-selected → prompt-attached → files-attached → submit-started → submit-observed → response-streaming → response-complete`

`submit-started` is persisted immediately before the actual ChatGPT send action. If that persistence fails, the prompt is not submitted. If an error happens after that boundary and delivery cannot be proven absent, the work is quarantined as `SUBMISSION_UNCERTAIN` rather than retried.

## Structured health and circuit breakers

Council now maintains bounded private health evidence for managed agents and exposes only safe summaries:

- healthy / sleeping / busy;
- stalled;
- usage/message limited;
- signed out;
- disconnected;
- conversation or browser surface missing;
- quarantined after ambiguous submission.

Defaults include a 60-minute usage-limit cooldown, exponential transient connection cooldown capped at 15 minutes, signed-out blocking until healthy evidence returns, and quarantine for ambiguous submissions. Sleeping alone never counts as a failure.

## Loop budgets and escalation

Default autonomy budgets prevent runaway collaboration loops:

- 60 managed ChatGPT turns per project per hour;
- 12 automatic wakes per target per hour;
- 6 automatic spawn intents per project per hour;
- 6 consecutive recovery attempts per agent;
- 200 active durable items per project;
- 60-second equivalent-wake cooldown;
- correlation depth capped at 12;
- stale queued work review after 6 hours.

Blocked, limited, stalled, signed-out, missing-conversation, policy-exhausted, and uncertain work can produce one coalesced escalation to the user-selected manager. The manager remains responsible for reassignment, review, replacement-agent spawning, or waiting for operator/session recovery.

## Supervisor integration

- Selecting a Project Manager still schedules an initial scan after a short delay and then every 20 minutes.
- Periodic scans are now durable manager-observation intents rather than direct timer-driven browser calls.
- Agent screenshots remain sequential and scroll to the bottom of each saved conversation before capture.
- Clearing the selected manager cancels future queued periodic observations without deleting history.
- Supervisor observations feed structured agent health while retained screenshots/analysis continue using the bounded observation archive introduced in 3.4.

## Safe status, audit and Electron visibility

- New authenticated read-only MCP tools: `council_autonomy_status` and `council_autonomy_audit`.
- Audit is append-only and bounded to 10,000 events / 30 days by default.
- Safe audit/status data contains IDs, state transitions, failure codes, cooldowns and budget counts only; conversation URLs, private checkpoints, prompt bodies, credentials, local paths and screenshot bytes are excluded/redacted.
- The Electron workspace surfaces durable queue counts, uncertain work, circuit breakers and per-agent health alongside the project tabs.

## Compatibility and migration

Council 3.4 rooms, tasks, messages, decisions, wake records, managed identities, conversation bindings, private checkpoints, manager selection and observation history remain valid. New autonomy work, audit, health and budget files are additive and versioned; no reset is required.
