# CodexWeb Council 3.2.0

Council 3.2.0 is the vNext reliability and observability release for shared Council state, managed execution, presence, wake lifecycle, and repository-bound work.

## Added

- Added canonical Council synchronization with atomic public snapshots, opaque continuation cursors, and typed `RESYNC_REQUIRED` recovery instead of renderer-owned loopback polling.
- Added a main-process Council connection supervisor that preserves the last authoritative shared projection across local runtime failures and publishes explicit `live`, `stale`, and error states.
- Added ephemeral 60-second agent presence leases (`unknown`, `fresh`, `stale`) independently from durable `awake`, `sleeping`, and `offline` status.
- Added sanitized GitHub workspace binding (`repoId`, owner, name, default branch, immutable base commit) with Lead-only binding and typed `STALE_BASE` receipts when repository HEAD moves.
- Added capability truth derived from live RuntimeSupervisor evidence, including immediate capability refresh without mutating the canonical Council cursor or projection.
- Added canonical wake lifecycle observability: `queued → dispatched → target-running → replied`, plus `failed` and durable `expired` terminal states, transition timestamps, delivery attempts, TTL expiry, and legacy wake compatibility.

## Fixed

- Fixed the renderer treating local loopback/Tunnel availability as the truth for shared Council rooms, messages, participants, and tasks.
- Fixed authoritative shared state being replaced with offline/empty data when local execution capabilities fail.
- Fixed configured Tunnel state being treated as runtime readiness; action availability now fails closed until live evidence exists.
- Fixed wake queue capacity/status disagreement where `delivering` work could fill the queue while status reported zero pending wakes.
- Fixed queued canonical wakes being invisible to capacity, decision gating, and resurrection context.
- Fixed abandoned wake records holding queue capacity or decision gates indefinitely by durably reaping expired wakes exactly once.
- Fixed UI presence semantics so stale heartbeat evidence does not rewrite durable agent status to offline.

## Compatibility and security

- Existing persisted Council state remains readable; legacy `pending` and `delivering` wakes remain recognized while new wakes use the canonical vNext lifecycle.
- Repository workspace state stores identity and immutable base metadata only; GitHub credentials and local filesystem paths are rejected from the shared project boundary.
- Shared Council truth and local action capabilities remain separate: loss of local Tunnel/browser capability does not erase synchronized collaboration state.
- The existing `CodexWeb Council` connector identity and Electron application identity are retained for in-place upgrades.

## Verification gate

A 3.2 release is permitted only after the release SHA passes:

- synchronized version, dependency audit, TypeScript, root Council/runtime tests, runtime build, and smoke gates;
- active Electron/Council launcher contract tests;
- Windows Electron package + packaged smoke;
- Linux Electron package + packaged smoke;
- macOS Electron package + packaged smoke;
- release workflow builds for macOS ARM64, macOS Intel, Linux x64, and Windows x64;
- macOS embedded runtime and packaged application signature verification;
- checksummed GitHub Release asset publication with every published asset represented in `checksums.txt`.
